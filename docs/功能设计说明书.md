# 1. 文档介绍

## 1.1 编写目的
本文档用于明确音乐平台Web前端项目的功能设计方案、界面交互逻辑与模块实现规则，为前端开发人员提供详细的功能实现依据，统一开发标准与交互规范，同时作为项目功能验收与测试的参考标准，保障项目功能符合课程考核要求与用户使用需求。

本文档覆盖音乐平台Web前端项目的系统概述、功能需求说明、五大核心模块的详细功能设计，以及前台界面的布局设计、页面跳转逻辑与交互规则。文档仅针对前端功能与界面进行设计说明，不包含后端服务的详细设计内容。

## 1.3 读者对象
- 项目开发小组成员
- Web前端框架技术课程考核教师
- 项目功能测试与评审人员

## 1.4 术语与缩写解释
|术语或缩写|解释|

# 2. 系统概述

## 2.1 系统说明
- 系统名称：音乐平台Web前端系统
- 任务提出者：计算机学院《Web前端框架技术》课程组
- 开发者：课程期末考核项目小组
- 用户群：有在线音乐收听、个性化歌单管理需求的互联网普通用户

## 2.2 项目背景
在线音乐平台已成为互联网用户日常娱乐的核心产品形态，前端交互体验是音乐平台核心竞争力之一。本项目为课程期末实践考核项目，以Vue框架为核心技术栈，开发一款具备完整基础功能的Web音乐平台，通过实战检验组件化开发、路由管理、状态管理、前后端交互等核心前端技术的掌握程度。

## 2.3 系统任务
1. 完成包含登录注册、音乐推荐、播放详情、个人中心、确认弹窗五大核心页面的单页应用开发。
2. 采用组件化开发模式拆分通用组件与页面组件，保障代码复用性与可维护性。
3. 实现完整的用户操作流程与交互逻辑，结合动画效果提升用户体验。
4. 通过Mock+Axios模拟前后端完整交互流程，使用Pinia实现全局状态统一管理。
5. 实现响应式布局，保障多设备下的正常显示与操作。

# 3. 需求说明

## 3.1 整体需求
本系统为基于Vue.js的单页Web音乐平台，面向普通用户提供音乐浏览、播放、歌单管理等核心服务。系统采用Vue工程化开发模式，通过Vue Router实现页面无刷新跳转，通过组件化拆分提升代码复用性，通过Pinia管理全局登录状态、播放状态与用户数据，结合Mock技术模拟后端接口，实现完整的前端业务闭环。系统需保证界面美观、交互流畅、操作逻辑符合用户习惯，并支持多终端适配。

## 3.2 功能需求

### 3.2.1 需求编号规则
功能设计采用与需求规格说明书一致的编号规则，格式为：`FUN-模块标识-功能序号`，二级功能在一级功能编号后追加层级序号。
- 模块标识：USER（用户认证）、RECOMMEND（音乐推荐）、PLAYER（音乐播放）、USERCENTER（个人中心）、COMMON（通用交互）
- 功能序号：按功能层级从001开始递增编号

### 3.2.2 总体模块划分
系统共划分为5个功能模块：
1. **用户认证模块**：负责账号登录、账号注册、路由权限拦截，是系统的入口与权限屏障。
2. **音乐推荐模块**：负责首页音乐推荐、分类浏览、关键词搜索与全局导航，是用户浏览音乐的核心入口。
3. **音乐播放模块**：负责歌曲详情展示、歌词显示、播放控制、进度管理，是音乐播放的核心功能模块。
4. **个人中心模块**：负责用户歌单增删改查、歌单内歌曲管理、个人信息设置，是用户个性化数据维护模块。
5. **通用交互模块**：负责敏感操作二次确认、操作结果提示等全局通用组件，保障操作安全与反馈明确。

# 4. 功能性需求设计

## 4.1 用户认证模块（FUN-USER）

|模块名称|用户认证模块|
|---|---|
|模块简介|系统入口模块，实现用户身份认证与权限控制，保障核心页面仅登录用户可访问|
|模块功能列表|账号登录、账号注册、路由权限拦截|

|序号|一级功能|功能编号|二级功能|功能编号|
|---|---|---|---|---|
|1|账号登录|FUN-USER-001|表单信息输入|FUN-USER-001-01|
||||表单校验|FUN-USER-001-02|
||||登录状态存储|FUN-USER-001-03|
|2|账号注册|FUN-USER-002|注册信息输入|FUN-USER-002-01|
||||注册信息校验|FUN-USER-002-02|
||||注册结果反馈|FUN-USER-002-03|
|3|路由权限拦截|FUN-USER-003|未登录跳转拦截|FUN-USER-003-01|
||||登录状态全局同步|FUN-USER-003-02|

### 4.1.1 账号登录功能（FUN-USER-001）
#### 4.1.1.1 表单信息输入（FUN-USER-001-01）
设计登录表单，包含账号输入框、密码输入框、登录提交按钮，以及“去注册”跳转链接。输入框使用`v-model`实现数据双向绑定，实时同步用户输入内容。

#### 4.1.1.2 表单校验（FUN-USER-001-02）
前端实现表单校验逻辑：账号、密码均不能为空；账号长度限制为4-16位；密码长度限制为6-20位。校验不通过时，输入框下方展示对应错误提示文字，禁用提交按钮。

#### 4.1.1.3 登录状态存储（FUN-USER-001-03）
校验通过后，通过Axios提交登录请求至Mock接口；接口返回成功后，将用户登录凭证与基础信息存入Pinia全局状态与本地存储，自动跳转至推荐音乐首页，并同步更新全局导航栏登录状态。

### 4.1.2 账号注册功能（FUN-USER-002）
#### 4.1.2.1 注册信息输入（FUN-USER-002-01）
设计注册表单，包含账号、密码、确认密码三个输入框，以及注册提交按钮、“返回登录”跳转链接，通过`v-if`实现登录/注册表单的无缝切换。

#### 4.1.2.2 注册信息校验（FUN-USER-002-02）
校验规则：账号、密码、确认密码均非空；账号格式与长度符合要求；两次输入密码完全一致。任一校验不通过时，展示对应错误提示。

#### 4.1.2.3 注册结果反馈（FUN-USER-002-03）
校验通过后提交注册请求，接口返回成功时弹出成功提示，自动跳转回登录页面；返回失败时展示失败原因，保留用户已输入内容。

### 4.1.3 路由权限拦截（FUN-USER-003）
#### 4.1.3.1 未登录跳转拦截（FUN-USER-003-01）
通过Vue Router全局前置守卫实现权限校验：用户访问需要登录的页面时，先校验本地是否存在有效登录状态；不存在则强制跳转至登录页面，并携带原页面路径，登录成功后可直接回跳。

#### 4.1.3.2 登录状态全局同步（FUN-USER-003-02）
登录状态通过Pinia全局共享，所有页面均可实时读取；用户触发退出登录时，清除Pinia状态与本地存储数据，跳转回登录页面。

||||歌曲卡片展示|FUN-RECOMMEND-001-02|
|2|音乐分类浏览|FUN-RECOMMEND-002|分类标签展示|FUN-RECOMMEND-002-01|
||||分类筛选切换|FUN-RECOMMEND-002-02|
|3|音乐搜索功能|FUN-RECOMMEND-003|关键词输入|FUN-RECOMMEND-003-01|

### 4.2.1 推荐音乐展示（FUN-RECOMMEND-001）
#### 4.2.1.1 音乐列表渲染（FUN-RECOMMEND-001-01）
页面加载时通过Axios请求Mock接口获取推荐音乐列表，使用`v-for`指令批量渲染音乐数据，支持列表懒加载与分页展示。

#### 4.2.1.2 歌曲卡片展示（FUN-RECOMMEND-001-02）
每首歌曲以卡片形式展示，包含歌曲封面、歌曲名称、歌手名称信息；卡片添加悬停动画效果，点击卡片跳转至对应歌曲的播放详情页面。

### 4.2.2 音乐分类浏览（FUN-RECOMMEND-002）
#### 4.2.2.1 分类标签展示（FUN-RECOMMEND-002-01）
页面侧边栏展示音乐分类标签，包含全部、流行、摇滚、民谣、电子、古典等分类，使用`v-bind:class`实现选中状态样式切换。

#### 4.2.2.2 分类筛选切换（FUN-RECOMMEND-002-02）
点击分类标签时，通过计算属性实时过滤音乐列表，仅展示对应分类的歌曲，切换过程添加淡入淡出过渡效果。

### 4.2.3 音乐搜索功能（FUN-RECOMMEND-003）
#### 4.2.3.1 关键词输入（FUN-RECOMMEND-003-01）
页面顶部设置搜索输入框，通过`v-model`绑定搜索关键词，支持实时输入与清空操作。

#### 4.2.3.2 搜索结果匹配（FUN-RECOMMEND-003-02）
通过侦听器监听关键词变化，实时匹配歌曲名称与歌手名称，过滤展示符合条件的结果；关键词为空时展示全部推荐音乐。

### 4.2.4 全局导航功能（FUN-RECOMMEND-004）
#### 4.2.4.1 页面跳转导航（FUN-RECOMMEND-004-01）
顶部固定导航栏，包含平台logo、首页、个人中心、退出登录等入口，通过Vue Router实现页面无刷新跳转。

#### 4.2.4.2 导航状态高亮（FUN-RECOMMEND-004-02）
通过路由元信息匹配当前页面，对应当前页面的导航项添加高亮样式，明确用户当前所在页面。

### 4.3.1 歌曲详情展示（FUN-PLAYER-001）
#### 4.3.1.1 基础信息展示（FUN-PLAYER-001-01）
页面加载时根据路由参数获取歌曲ID，请求接口获取歌曲详情，展示歌曲封面、歌曲名称、歌手、专辑名称等基础信息。

#### 4.3.1.2 音乐简介展示（FUN-PLAYER-001-02）
展示歌曲创作背景、歌词含义等简介内容，内容过长时支持折叠/展开切换。

### 4.3.2 歌词展示功能（FUN-PLAYER-002）
#### 4.3.2.1 歌词文本展示（FUN-PLAYER-002-01）
解析接口返回的逐行歌词数据，以列表形式展示完整歌词内容。

#### 4.3.2.2 歌词滚动同步（FUN-PLAYER-002-02）
根据当前播放进度匹配对应歌词行，对当前播放行添加高亮样式，歌词区域自动滚动至当前行，滚动过程添加平滑过渡效果。

### 4.3.3 播放控制功能（FUN-PLAYER-003）
#### 4.3.3.1 播放/暂停控制（FUN-PLAYER-003-01）
底部播放栏设置播放/暂停按钮，点击切换播放状态，按钮图标同步切换，播放状态存入Pinia全局管理。

#### 4.3.3.2 上一首/下一首切歌（FUN-PLAYER-003-02）
设置上一首、下一首切换按钮，点击后切换播放列表中的相邻歌曲，同步更新页面所有歌曲信息与歌词。

### 4.3.4 播放进度管理（FUN-PLAYER-004）
#### 4.3.4.1 进度条展示（FUN-PLAYER-004-01）
展示歌曲总时长与当前播放时长，进度条实时更新播放进度，进度填充添加渐变动画效果。

#### 4.3.4.2 进度拖拽调整（FUN-PLAYER-004-02）
支持拖拽进度条滑块调整播放位置，拖拽结束后同步更新播放进度与歌词匹配位置。

### 4.4.1 歌单管理功能（FUN-USERCENTER-001）
#### 4.4.1.1 歌单列表展示（FUN-USERCENTER-001-01）
页面加载时获取用户自建歌单列表，以卡片形式展示歌单封面、名称、歌曲数量，点击歌单可展开查看歌单内歌曲。

#### 4.4.1.2 新增歌单（FUN-USERCENTER-001-02）
提供“新建歌单”按钮，点击弹出表单，输入歌单名称与简介后提交，创建成功后实时更新歌单列表。

#### 4.4.1.3 修改歌单信息（FUN-USERCENTER-001-03）
每个歌单提供编辑入口，支持修改歌单名称、简介信息，提交后同步更新列表展示。

#### 4.4.1.4 删除歌单（FUN-USERCENTER-001-04）
每个歌单提供删除按钮，点击后触发二次确认弹窗，用户确认后执行删除操作，删除后列表实时刷新。

### 4.4.2 歌曲管理功能（FUN-USERCENTER-002）
#### 4.4.2.1 歌单内歌曲展示（FUN-USERCENTER-002-01）
展开歌单后，以列表形式展示歌单内所有歌曲，包含歌曲名称、歌手、时长信息。

#### 4.4.2.2 添加歌曲至歌单（FUN-USERCENTER-002-02）
推荐页歌曲卡片提供“添加到歌单”操作，点击后展示用户歌单列表，选择目标歌单即可完成添加。

#### 4.4.2.3 从歌单删除歌曲（FUN-USERCENTER-002-03）
歌单内每首歌曲提供移除按钮，点击后触发二次确认弹窗，确认后从歌单中移除该歌曲。

### 4.4.3 个人设置功能（FUN-USERCENTER-003）
#### 4.4.3.1 个人信息查看（FUN-USERCENTER-003-01）
页面侧边栏展示用户头像、昵称、账号等基础个人信息。

#### 4.4.3.2 个人信息修改（FUN-USERCENTER-003-02）
提供信息编辑入口，支持修改用户昵称、头像，提交后同步更新全局用户状态。

# 5. 界面设计

## 5.1 界面的功能

### 5.1.1 前台界面
本系统为面向普通用户的音乐平台，全部为前台用户界面，共包含4个页面级界面与1个全局组件界面，具体如下：
1. **登录/注册页面**：系统入口，完成用户身份认证与账号注册。
2. **推荐音乐页面**：系统首页，完成音乐浏览、分类筛选、搜索与全局导航。
3. **播放音乐详情页面**：核心播放页，完成歌曲播放、详情查看、歌词展示。
4. **用户个人中心页面**：个人数据页，完成歌单管理、歌曲维护、个人设置。
5. **音乐信息提示弹窗**：全局通用组件，完成操作二次确认与结果提示。

### 5.1.2 后台界面
本项目为前端音乐平台演示项目，无后台管理系统，不包含后台管理界面。

## 5.2 界面关系

### 5.2.1 登录/注册页面
#### 页面说明
系统唯一的公开页面，作为平台访问入口，采用左右分栏的居中卡片式布局，左侧为平台品牌与宣传区域，右侧为表单区域，支持登录、注册状态一键切换。

#### 页面迁移图
- 登录表单校验通过 → 提交登录 → 登录成功 → 跳转至推荐音乐首页
- 登录表单点击“去注册” → 切换为注册表单
- 注册表单点击“返回登录” → 切换为登录表单
- 注册提交成功 → 自动返回登录表单
- 未登录用户访问其他页面 → 路由拦截 → 跳转至本页面
- 登录状态下访问本页面 → 自动跳转至推荐音乐首页

#### 页面布局设计
页面整体采用深色主题风格，背景为渐变音乐元素底纹；中部居中展示宽900px的内容卡片，左侧40%区域展示平台logo、名称与slogan；右侧60%区域为表单区，包含标题、输入框组、操作按钮、底部跳转链接，输入框带图标与校验提示，按钮采用主色调圆角样式。

### 5.2.2 推荐音乐页面
#### 页面说明
平台首页，采用顶部导航+侧边分类+主内容区的经典布局，是用户浏览音乐的核心页面，承载音乐推荐、分类、搜索三大核心浏览功能。

#### 页面迁移图
- 点击顶部导航“首页” → 停留/返回本页面
- 点击顶部导航“个人中心” → 跳转至用户个人中心页面
- 点击顶部导航“退出登录” → 清除登录状态 → 跳转至登录页面
- 点击歌曲卡片 → 跳转至对应歌曲的播放详情页面
- 点击左侧分类标签 → 本页面刷新筛选音乐列表
- 输入搜索关键词 → 本页面实时展示搜索结果
- 点击歌曲“添加到歌单” → 弹出歌单选择浮层

#### 页面布局设计
顶部为60px高的固定导航栏，左侧为200px宽的分类侧边栏，主内容区自适应剩余宽度。主内容区顶部为搜索框，下方为音乐卡片网格区域，每行展示5张歌曲卡片，卡片带封面、名称、歌手信息，悬停时上浮并显示操作按钮。

### 5.2.3 播放音乐详情页面
#### 页面说明
歌曲播放核心页面，采用顶部导航+左右分栏+底部播放栏的布局，聚焦歌曲播放体验，提供完整的播放控制与歌词展示。

#### 页面迁移图
- 点击顶部导航“首页” → 跳转至推荐音乐页面
- 点击顶部导航“个人中心” → 跳转至用户个人中心页面
- 点击底部播放栏“上一首/下一首” → 本页面切换歌曲内容
- 点击返回按钮 → 返回上一级页面
- 拖拽进度条 → 本页面更新播放进度与歌词位置

#### 页面布局设计
顶部保留全局导航栏，主体区域左右分栏：左侧40%区域展示大尺寸歌曲封面、歌曲基础信息、歌曲简介；右侧60%区域为歌词展示区，歌词居中排列，当前行高亮。页面底部为固定高度的播放控制栏，包含上一首、播放/暂停、下一首按钮，以及进度条与时长显示。

### 5.2.4 用户个人中心页面
#### 页面说明
用户个性化管理页面，采用顶部导航+左侧个人信息栏+右侧主内容区的布局，承载歌单管理、歌曲维护、个人设置功能。

#### 页面迁移图
- 点击顶部导航“首页” → 跳转至推荐音乐页面
- 点击“新建歌单” → 弹出新建歌单表单弹窗
- 点击歌单“编辑” → 弹出编辑歌单表单弹窗
- 点击歌单“删除” → 弹出操作确认弹窗 → 确认后刷新歌单列表
- 点击歌单卡片 → 展开歌单内歌曲列表
- 点击歌曲“移除” → 弹出操作确认弹窗 → 确认后刷新歌曲列表
- 点击个人信息“编辑” → 弹出个人信息修改弹窗

#### 页面布局设计
顶部保留全局导航栏，左侧240px宽的侧边栏展示用户头像、昵称、账号信息与功能菜单；右侧主内容区展示歌单列表，歌单以卡片形式横向排列，点击展开后下方嵌套展示歌曲列表，每个歌单与歌曲项均附带操作按钮。

### 5.2.5 音乐信息提示弹窗
#### 页面说明
全局通用模态组件，覆盖于所有页面之上，用于敏感操作二次确认与操作结果轻量提示，保障用户操作安全与反馈明确。

#### 页面迁移图
- 触发删除类敏感操作 → 弹窗淡入出现
- 点击弹窗“确认”按钮 → 执行对应操作 → 弹窗淡出关闭
- 点击弹窗“取消”按钮/点击遮罩层 → 不执行操作 → 弹窗淡出关闭
- 触发操作结果提示 → 弹窗淡入出现 → 2秒后自动淡出关闭

#### 页面布局设计
采用居中模态弹窗样式，底层为半透明黑色遮罩，中间为白色圆角弹窗卡片。确认类弹窗包含标题、提示文案、底部确认/取消双按钮；提示类弹窗包含状态图标、提示文字，无操作按钮。弹窗出现与消失均添加淡入淡出过渡动画。
