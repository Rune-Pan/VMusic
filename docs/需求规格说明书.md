# 1. 文档介绍

## 1.1 编写目的
本文档用于明确《基于Vue框架的音乐平台Web前端项目》的功能需求与非功能需求，界定项目开发范围与验收标准，为项目开发人员提供开发依据，同时作为课程期末考核的验收参考文档，确保项目满足课程考核要求与用户使用需求。

## 1.2 文档范围
本文档覆盖音乐平台Web前端项目的项目背景、整体需求、功能性需求、非功能性需求，包含用户认证、音乐推荐、播放详情、个人中心、通用弹窗五大核心模块的功能细节，以及技术实现、界面体验、兼容性等非功能要求，仅针对前端开发范围进行定义，不包含后端服务的详细设计。

## 1.3 读者对象
- 项目开发小组成员
- Web前端框架技术课程考核教师
- 项目评审相关人员

## 1.4 术语与缩写解释
|术语或缩写|解释|
|---|---|
|Vue.js|一套用于构建用户界面的渐进式JavaScript前端框架|
|SPA|单页应用（Single Page Application），仅在页面初始化时加载资源，页面跳转通过路由实现局部刷新|
|Vue Router|Vue.js官方路由管理器，用于实现单页应用的路由跳转与导航管理|
|Axios|基于Promise的HTTP客户端，用于前端与后端API进行数据交互|
|Pinia|Vue.js状态管理库，用于全局状态共享与数据统一管理|
|Mock|数据模拟技术，可在无后端服务的情况下模拟接口返回数据|
|响应式布局|页面可根据不同设备屏幕尺寸自动调整布局，保障多端显示效果|

# 2. 项目介绍

## 2.1 项目说明
- 产品名称：音乐平台Web网站
- 任务提出者：计算机学院《Web前端框架技术》课程组
- 开发者：课程期末考核项目小组
- 用户群：有在线音乐收听、歌单管理需求的互联网用户

## 2.2 项目背景
随着互联网流媒体技术发展，在线音乐平台已成为用户日常娱乐的核心工具之一。本项目为《Web前端框架技术》课程期末考核实践项目，以Vue前端框架为核心开发一款具备基础音乐播放与歌单管理能力的Web音乐平台，通过项目实践检验Vue框架核心知识点的掌握程度，提升前端工程化开发、组件化设计与前后端交互的综合实践能力。

## 2.3 项目目标
1. 基于Vue项目化开发模式，完成包含5个核心页面的音乐平台单页应用，全面覆盖课程核心知识点。
2. 采用组件化开发模式拆分页面与通用组件，提升代码复用性与可维护性。
3. 实现路由管理、数据渲染、交互逻辑等核心功能，保障基础用户体验。
4. 拓展实现响应式布局、动画效果、Mock数据模拟、全局状态管理等创新功能，提升项目完成度。
5. 掌握前后端交互流程与状态管理方案，形成完整的前端项目开发能力。

## 2.4 项目用户
1. 游客用户：仅可访问登录注册页面，无法使用平台核心功能。
2. 注册用户：完成登录后，可使用音乐浏览、播放、歌单管理、个人设置等全部平台功能。

# 3. 需求说明

## 3.1 整体需求
本项目为基于Vue框架的单页Web音乐平台，需实现用户登录注册、音乐推荐浏览、歌曲播放详情、个人歌单管理、操作确认弹窗五大核心功能模块。项目需采用Vue工程化开发模式，使用Vue Router实现路由管理，完成页面间无刷新跳转；通过组件化拆分实现UI复用；结合Mock与Axios模拟前后端交互；通过Pinia实现全局状态管理。同时需满足界面美观、交互流畅、多端适配的体验要求。

## 3.2 功能需求

### 3.2.1 需求编号规则
功能性需求采用“模块前缀-功能层级-序号”的编号规则，格式为：`FUN-模块标识-功能序号`。
- 模块标识：USER（用户认证）、RECOMMEND（音乐推荐）、PLAYER（音乐播放）、USERCENTER（个人中心）、COMMON（通用交互）
- 功能序号：按功能层级从001开始递增编号

### 3.2.2 总体模块划分
本项目共划分为5个功能模块，分别为：
1. 用户认证模块：实现账号登录、注册与路由权限校验。
2. 音乐推荐模块：实现首页音乐推荐、分类浏览、搜索与全局导航。
3. 音乐播放模块：实现歌曲详情展示、歌词显示、播放控制与进度管理。
4. 个人中心模块：实现用户歌单增删改、歌单内歌曲管理与个人信息设置。
5. 通用交互模块：实现敏感操作二次确认弹窗、信息提示等通用交互组件。

# 4. 功能性需求

## 4.1 用户认证模块（FUN-USER）

|模块名称|用户认证模块|
|---|---|
|模块简介|负责平台用户的账号登录、账号注册与路由权限拦截，是用户访问平台核心功能的入口|

|序号|一级功能|功能编号|二级功能|功能编号|
|---|---|---|---|---|
|1|账号登录|FUN-USER-001|表单信息输入|FUN-USER-001-01|

|2|账号注册|FUN-USER-002|注册信息输入|FUN-USER-002-01|
||||注册信息校验|FUN-USER-002-02|
||||注册结果反馈|FUN-USER-002-03|
|3|路由权限拦截|FUN-USER-003|未登录跳转拦截|FUN-USER-003-01|
||||登录状态全局同步|FUN-USER-003-02|

### 4.1.1 账号登录功能（FUN-USER-001）
用户通过输入账号、密码完成平台登录，是访问平台核心功能的前置条件。
#### 4.1.1.1 表单信息输入（FUN-USER-001-01）
提供账号、密码输入框与登录提交按钮，支持用户输入登录凭证；提供“去注册”跳转入口，可切换至注册页面。
#### 4.1.1.2 表单校验（FUN-USER-001-02）
对用户输入的账号、密码进行非空校验与格式校验，输入不符合规则时给出对应错误提示。
#### 4.1.1.3 登录状态存储（FUN-USER-001-03）
登录验证通过后，存储用户登录状态与基础信息，自动跳转至推荐音乐首页，全局同步用户登录状态。

### 4.1.2 账号注册功能（FUN-USER-002）
支持新用户提交账号信息完成注册，获取平台使用权限。
#### 4.1.2.1 注册信息输入（FUN-USER-002-01）
提供账号、密码、确认密码等注册信息输入框，提供“返回登录”跳转入口。
#### 4.1.2.2 注册信息校验（FUN-USER-002-02）
对注册信息进行非空、格式、两次密码一致性校验，校验不通过时给出明确提示。
#### 4.1.2.3 注册结果反馈（FUN-USER-002-03）
注册信息提交后，返回注册成功/失败结果，成功后引导用户跳转至登录页面。

### 4.1.3 路由权限拦截（FUN-USER-003）
保障平台核心页面仅登录用户可访问。
#### 4.1.3.1 未登录跳转拦截（FUN-USER-003-01）
用户未登录状态下，访问推荐、播放、个人中心等页面时，自动拦截并跳转至登录页面。
#### 4.1.3.2 登录状态全局同步（FUN-USER-003-02）
登录状态在全平台页面同步，用户退出登录后，自动清除状态并返回登录页。

### 4.2.1 推荐音乐展示（FUN-RECOMMEND-001）
首页展示热门推荐音乐列表，供用户浏览与选择播放。

# 5. 非功能性需求

## 5.1 技术实现要求
1. **基础技术栈**：使用HTML构建页面结构、CSS设计基础样式、JavaScript实现业务逻辑，基于Vue.js框架进行项目化开发，使用Vue Router实现单页应用路由管理。
2. **工程化要求**：采用标准Vue项目结构，使用组件化开发模式拆分页面组件与通用组件，代码结构清晰、命名规范，覆盖class/style绑定、条件渲染、列表渲染、事件绑定、双向绑定、计算属性、侦听器、插槽等课程核心知识点。
3. **前后端交互**：使用Axios实现HTTP请求交互，通过Mock技术模拟后端接口数据，完成登录、数据获取、提交等完整流程。
4. **状态管理**：使用Pinia状态管理库实现全局状态管理，统一维护用户登录状态、播放状态、歌单数据等全局数据，保障数据一致性。

## 5.2 界面与体验要求
1. **视觉一致性**：全平台页面风格、色彩、字体保持统一，界面美观整洁，布局合理。
2. **动画效果**：使用Vue过渡效果实现页面切换、弹窗展示、元素交互的平滑动态效果，提升交互体验。
3. **交互反馈**：所有可操作元素提供悬停、点击反馈，操作结果有明确提示，交互逻辑符合用户使用习惯。

## 5.3 性能与兼容性要求
1. **响应式布局**：平台适配PC、平板、手机等不同尺寸设备，在各分辨率下均有良好的显示与操作体验。
2. **单页体验**：页面跳转通过路由实现局部刷新，无整页重载，保证操作流畅性。
3. **浏览器兼容**：支持主流现代浏览器的正常访问与功能运行。
