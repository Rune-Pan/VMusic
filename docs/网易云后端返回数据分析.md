# 网易云 API 返回数据与前端消费说明

[文档导航](./README.md) · [API 启动](./NeteaseAPI启动说明.md) · [架构总览](./架构总览.md)

本文只整理听潮前端封装和使用的接口，不是第三方后端全部接口的手册。
接口定义以 [src/api/](../src/api/) 与仓库内后端模块为准；返回字段可能随账号和上游变化。
以下 JSON 是删减后的结构示例，不是完整抓包或稳定的服务承诺。

## 请求约定

- 前端基础路径由 `VITE_NETEASE_API_URL` 指定，默认 `/api`。
- 开发环境由 Vite 去掉 `/api` 转发到端口 3000；Vercel 由 `api/index.js` 处理同域 API。
- 本文接口表省略前缀，例如 `/song/detail` 在前端实际请求 `/api/song/detail`。
- [request.js](../src/utils/request.js) 使用凭证和 15 秒超时，返回 `response.data`，不返回完整 Axios 响应。
- 接口封装中的 `POST` 多数仍通过 Axios `params` 传递查询参数，不应误写为固定 JSON 请求体。
- 部分缓存命中时返回 `{ songs, privileges }` 或 `{ playlist }` 等子集，没有完整的网络响应字段；消费代码不能假设每次都有 `code`。

HTTP 状态和 JSON 内的 `code` 要分别检查。二维码检查的 `code` 表示扫码状态，
也不能直接套用普通接口的成功 / 失败含义。

## 认证接口

来源：[src/api/auth.js](../src/api/auth.js)、[user Store](../src/stores/user.js)。

| 封装               | 请求                    | 主要参数                       | 使用的返回字段               |
| ------------------ | ----------------------- | ------------------------------ | ---------------------------- |
| `loginWithPhone`   | `POST /login/cellphone` | `phone`、`password`            | `code`、`profile`、`account` |
| `loginWithCaptcha` | `POST /login/cellphone` | `phone`、`captcha`             | 同上                         |
| `captchaSent`      | `GET /captcha/sent`     | `phone`、`ctcode`、`timestamp` | `code`、`message`            |
| `loginQrCodeKey`   | `GET /login/qr/key`     | `timestamp`                    | `data.unikey`                |
| `loginQrCodeCheck` | `GET /login/qr/check`   | `key`、`timestamp`             | `code`、`cookie`             |
| `logout`           | `POST /logout`          | 无必填业务参数                 | 登出响应                     |

登录资料示例：

```json
{
  "code": 200,
  "account": { "id": 123456, "userName": "示例账号", "vipType": 0 },
  "profile": {
    "userId": 123456,
    "nickname": "示例昵称",
    "avatarUrl": "https://example.com/avatar.jpg"
  }
}
```

二维码由前端 `qrcode` 库生成，不调用 `/login/qr/create`。
二维码状态：800 过期、801 等待扫码、802 等待确认、803 授权成功。
成功后设置响应 Cookie，并请求 `/user/account` 获取资料。
文档和截图不得记录真实 Cookie 或登录凭证。

## 用户与历史

来源：[src/api/user.js](../src/api/user.js)。

| 封装                | 请求                 | 主要参数                    | 消费字段                   |
| ------------------- | -------------------- | --------------------------- | -------------------------- |
| `userAccount`       | `GET /user/account`  | `timestamp`                 | `profile`、`account`       |
| `userPlaylist`      | `GET /user/playlist` | `uid`、`limit`、`offset`    | `playlist` 数组            |
| `userPlayHistory`   | `GET /user/record`   | `uid`、`type`               | `weekData` 或 `allData`    |
| `userLikedSongsIDs` | `GET /likelist`      | 原始 `uid`、`timestamp`     | `ids` 数组                 |
| `updateUserProfile` | `POST /user/update`  | 昵称等资料参数、`timestamp` | 保留封装，当前没有界面入口 |

`/user/record` 中 `type=1` 对应最近一周、`type=0` 对应全部时间。
历史项包含 `song`、`playCount`、`score`；前端将歌曲与历史展示信息组合。
本地历史来自播放器，不通过此接口读取，清空本地历史不删除服务端记录。

用户歌单用于读取名称、封面、歌曲数、简介、`creator.userId` 等。
不要假设 `/user/playlist` 中每个歌单都携带完整 `tracks`；
详情和添加操作分别走对应接口。

## 歌曲、播放与评论

来源：[src/api/track.js](../src/api/track.js)。

| 封装              | 请求                 | 主要参数                              | 消费字段                                   |
| ----------------- | -------------------- | ------------------------------------- | ------------------------------------------ |
| `getMP3`          | `GET /song/url`      | `id`、`br`                            | `data[0].url/br/freeTrialInfo`             |
| `getTrackDetail`  | `GET /song/detail`   | 逗号分隔的 `ids`                      | `songs`、`privileges`                      |
| `getLyric`        | `GET /lyric`         | `id`                                  | `lrc.lyric`、`tlyric.lyric`                |
| `scrobble`        | `GET /scrobble`      | `id`、`sourceid`、`time`、`timestamp` | 听歌上报响应                               |
| `likeSong`        | `GET /like`          | `id`、`like`、`timestamp`             | 喜欢 / 取消喜欢响应                        |
| `getSongComments` | `GET /comment/music` | `id`、`limit`、`offset`               | `comments`、`hotComments`、`total`、`more` |

### 音频地址与试听

```json
{
  "code": 200,
  "data": [
    {
      "id": 347230,
      "url": "https://example.com/audio.mp3",
      "br": 320000,
      "freeTrialInfo": null
    }
  ]
}
```

`url` 可能为空，`freeTrialInfo` 非空表示试听片段。
前端会尝试播放可用片段并提示试听，不会把试听地址写入持久 URL 缓存。
音频 URL 有时效，播放器加载失败后清除该项缓存并重取一次。

`br` 使用个人设置的音质偏好，默认 320000。
选择无损偏好不保证上游一定返回无损或完整音频。
歌曲详情的 `dt` 是毫秒，`scrobble.time` 是上报的秒数，不能混用。

### 歌曲与权限字段

```json
{
  "code": 200,
  "songs": [
    {
      "id": 347230,
      "name": "示例歌曲",
      "ar": [{ "id": 123, "name": "示例歌手" }],
      "al": {
        "id": 456,
        "name": "示例专辑",
        "picUrl": "https://example.com/cover.jpg"
      },
      "dt": 240000
    }
  ],
  "privileges": [{ "id": 347230, "cs": false, "fee": 0, "pl": 320000 }]
}
```

| 字段                 | 当前用途                                                          |
| -------------------- | ----------------------------------------------------------------- |
| `id`、`name`         | 请求、列表定位与名称展示                                          |
| `ar`、`al`           | 歌手与专辑信息；部分搜索响应可能使用 `artists`、`album`           |
| `dt`                 | 元数据时长，毫秒；播放时以 Howler 实际时长为准                    |
| `privilege.cs`       | 无版权时限制播放                                                  |
| `privilege.fee`      | `4` 时限制播放；`1` 时显示需 VIP 的说明                           |
| `privilege.pl`       | `0` 时提示需 VIP，但当前仍允许尝试试听                            |
| `playable`、`reason` | `mapTrackPlayableStatus()` 附加的前端字段，不是上游保证存在的字段 |

当前 `isTrackPlayable()` 只在 `cs` 为真或 `fee === 4` 时返回 false。
无权限字段时先允许尝试，最终能否播放仍取决于音频 URL。
不得将它写成 `pl === 0` 必定不可点击，或宣称能改变账号权限。

### 原文与翻译歌词

```json
{
  "code": 200,
  "lrc": { "lyric": "[00:01.00]Original line" },
  "tlyric": { "lyric": "[00:01.00]翻译歌词" }
}
```

[music.fetchLyrics()](../src/stores/music.js) 分别调用 `parseLRC()`，
按相同 `rawTime` 标签匹配翻译，得到含 `time`、`rawTime`、`content`，
以及可选 `translation` 的数组，供播放页使用和缓存。
当前没有消费逐字歌词与罗马音字段，也没有 Mock 歌词备用源。

## 歌单、分类、推荐与榜单

来源：[src/api/playlist.js](../src/api/playlist.js)。

| 封装                     | 请求                      | 主要参数                         | 消费字段                                   |
| ------------------------ | ------------------------- | -------------------------------- | ------------------------------------------ |
| `recommendPlaylist`      | `GET /personalized`       | `limit`                          | `result`，含歌单 ID、名称、封面等          |
| `dailyRecommendPlaylist` | `GET /recommend/resource` | `timestamp` 等                   | `recommend`                                |
| `getPlaylistDetail`      | `GET /playlist/detail`    | `id`、`timestamp`                | `playlist`、`privileges`                   |
| `toplists`               | `GET /toplist`            | 无必填业务参数                   | `list`                                     |
| `playlistCatlist`        | `GET /playlist/catlist`   | 无必填业务参数                   | `sub`、`categories` 等                     |
| `topPlaylist`            | `GET /top/playlist`       | `cat`、`limit`、`offset`         | `playlists`、`more`、`total`               |
| `dailyRecommendTracks`   | `GET /recommend/songs`    | `timestamp`                      | `data.dailySongs`、`data.privileges`       |
| `createPlaylist`         | `POST /playlist/create`   | `name`、`privacy`、`timestamp`   | `code`、`id`                               |
| `deletePlaylist`         | `POST /playlist/delete`   | `id`、`timestamp`                | 保留底层封装，当前无界面入口               |
| `addTracksToPlaylist`    | `POST /playlist/tracks`   | `op`、`pid`、逗号分隔的 `tracks` | 添加或移除响应；当前添加弹窗使用 `op: add` |
| `getPlaylistComments`    | `GET /comment/playlist`   | `id`、`limit`、`offset`          | `comments`、`hotComments`、`total`、`more` |

歌单关键字段：

| 字段                                       | 用途与注意事项                                      |
| ------------------------------------------ | --------------------------------------------------- |
| `id`、`name`、`coverImgUrl`、`description` | 详情信息；推荐列表也可能使用 `picUrl`、`copywriter` |
| `creator.userId`                           | 判断是否为当前用户自己的歌单                        |
| `trackCount`                               | 总歌曲数，不保证等于首批 `tracks.length`            |
| `tracks`                                   | 已返回的歌曲列表，附加可播放状态                    |
| `trackIds`                                 | 全部歌曲 ID，用于继续获取详情                       |
| `playlist.subscribed`                      | 返回的订阅状态，不表示前端提供收藏操作              |

`getPlaylistDetail(id, true)` 的第二个参数用于跳过缓存。
新建歌单的简介只写入本地记录；当前歌单详情的移除操作也没有调用服务端删除接口。
写操作的边界见[功能设计](./功能设计说明书.md#创建与添加)。

## 搜索与歌手

来源：[others.js](../src/api/others.js)、[artist.js](../src/api/artist.js)。

| 封装              | 请求                                 | 主要参数                              | 消费字段                                |
| ----------------- | ------------------------------------ | ------------------------------------- | --------------------------------------- |
| `search`          | `GET /search`                        | `keywords`、`type`、`limit`、`offset` | `result` 中对应类型的结果数组           |
| `getArtistDetail` | `GET /artists` 与 `GET /artist/desc` | `id`                                  | `artist`、`hotSongs`、`briefDesc`       |
| `getArtistAlbums` | `GET /artist/album`                  | `id`、`limit`、`offset`               | `hotAlbums`、`more`，总数由可用字段回退 |
| `getArtistSongs`  | `GET /artist/songs`                  | `id`、`order`、`limit`、`offset`      | `songs`、`privileges`、`more`、`total`  |

搜索类型与主要结果：

| `type` | 内容 | 常用结果字段                               |
| ------ | ---- | ------------------------------------------ |
| 1      | 单曲 | `songs`，兼容封装中出现的嵌套 `song.songs` |
| 10     | 专辑 | `albums`                                   |
| 100    | 歌手 | `artists`                                  |
| 1000   | 歌单 | `playlists`                                |

`getArtistDetail()` 合并信息与简介请求，返回前端对象 `{ artist, hotSongs, desc }`。
详情使用杂项缓存，歌曲和专辑追加页走网络。歌手详情已接入；
搜索专辑和歌手专辑列表目前只展示，没有独立专辑详情页面。

## 缓存与错误排查

缓存表、TTL 和 LRU 参数统一见[架构总览](./架构总览.md#indexeddb-缓存)。
评论仅缓存首页，追加页不复用首页结果；试听 URL 不存持久缓存。

排查时依次记录：请求路径与参数、HTTP 状态、响应 `code`、必要业务字段、
账号状态、是否命中本地缓存。公开歌曲接口成功不代表登录和写入流程成功。

当前没有 `src/mock/`、`mockOrFetch()` 或 `VITE_USE_MOCK` 数据源开关。
前端没有邮箱登录、后端二维码图片生成和私人 FM 的调用封装。
后端虽保留大量通用接口，不应因此把未接入能力写进已完成功能清单。
