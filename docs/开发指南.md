## 代码入口

前端采用 Vue 3 Composition API、Vue Router、Pinia 和 Vite。
Axios 请求接口，Howler.js 播放音频，Dexie 管理 IndexedDB 缓存。

| 入口 | 职责 |
| --- | --- |
| [main.js](../src/main.js) / [App.vue](../src/App.vue) | 应用初始化、状态恢复、全局布局与预加载 |
| [router](../src/router/index.js) | 页面懒加载、登录守卫、标题与滚动恢复 |
| [stores](../src/stores/) | 用户、播放器、音乐内容和界面状态 |
| [api](../src/api/) / [request.js](../src/utils/request.js) | 接口封装、请求基址、凭证与响应处理 |
| [AlbumView](../src/views/AlbumView.vue) / [album.js](../src/api/album.js) | 受登录保护的专辑详情、完整曲目及可播放状态映射 |

## 请求与状态

开发环境：浏览器 `/api/*` → Vite 去掉 `/api` → `localhost:3000`。
代理配置见 [vite.config.js](../vite.config.js)，仅启动前端无法获取数据。
生产环境：`/api/*` → [api/index.js](../api/index.js) → 仓库内 Express 后端。
两种环境的 `VITE_NETEASE_API_URL` 均为 `/api`。

- Axios 携带凭证，成功时返回 `response.data`，失败时拒绝 Promise。
- 部分 POST 封装通过 `params` 传递参数，修改时应核对具体接口。
- 缓存命中可能只返回业务字段，不能假定每次都存在响应 `code`。
- HTTP 状态与 JSON `code` 分别检查；二维码的 `code` 表示扫码状态。

`user` 管理登录与喜欢列表，`player` 管理共享播放器与队列，
`music` 管理发现、歌词和歌单，`ui` 管理确认弹窗与 Toast。
localStorage 保存登录标记、播放偏好、本地历史和本地歌单。
浏览器登录标记仅作为恢复候选；异步路由守卫校验`/user/account`。明确失效清理会话并保留原路径，网络失败保留候选记录，在登录页显式重试。受保护接口返回301时触发统一过期处理。
本地记录与网易云账号数据的写入边界见[功能状态](./功能状态与验收.md#数据写入边界)。

### 歌词颜色偏好

个人设置 → 播放与歌词 → 歌词颜色由 [LyricColorSettings](../src/components/LyricColorSettings.vue) 提供，
通过共享响应式 [useLyricColors](../src/composables/useLyricColors.js) 同步预览与播放页。
`vmusic-lyric-colors` 在 localStorage 保存 `{ active, normal }`；各值为 `null`（跟随主题）或大写 `#RRGGBB`，
与账号无关，刷新、切歌、退出后重新登录保留，不跨设备同步。

当前行与普通行独立支持跟随主题、六种预设、原生取色器和十六进制输入；有效色值自动规范化并保存。
非法、未完成或过长输入保留上一有效色并行内提示；可逐项跟随主题或全部恢复默认。
播放页仅通过 `--lyric-active-color`、`--lyric-normal-color` 应用颜色，翻译与时间继承所在行颜色；
自定义色跨主题保持固定，悬停不覆盖。默认仍沿用主题及原有悬停行为，可读性提示不自动改色。
颜色即时生效，不触发播放或重建音源；原有字号、翻译与时间偏好仍需重新进入播放页生效。

## 播放与缓存

1. 列表通过 `mapTrackPlayableStatus(tracks, privileges)` 标记可播放状态。
2. [player Store](../src/stores/player.js) 获取歌曲详情、音频 URL 并创建 Howl。
3. 播放栏与播放页共用该 Store；进度读取 Howler，歌词由 `music` 解析。
4. 试听按实际音频时长显示，完整歌曲的元数据时长不能代替试听时长。
5. URL 加载失败会清除该曲目缓存并重取一次，第二次失败停止重试。

切歌以请求序号和 Howl 实例共同隔离；旧请求与回调不能更新新歌曲。
`playing` 跟随真实音频事件，`wantsPlay` 表示播放意图，加载期间仍可点击暂停。
手动选歌（含上/下一首）失败会停住；自动连播失败会有限跳过，每轮每首最多尝试一次。
单曲循环正常结束时重播，故障时允许跳过；浏览器播放权限拦截等待用户点击重试。
歌词通过 Store 的 `currentLyricsTrackId` 绑定曲目，页面订阅共享数据和 SWR 刷新。

播放器在路由挂载前恢复，详情页挂载只加载展示数据，不隐式播放。
沿用 `vmusic-player`，新增 `progressMs`、`durationMs`，老记录缺进度按零处理。
播放中每 5 秒保存，暂停、拖动、切歌和 `pagehide` 立即保存；恢复默认暂停。
点击继续后以实际音源时长校验位置，超过时长则归零，避免完整歌曲变试听后越界。
详情页直接浏览其他歌曲时不会改变播放任务；点击其歌词才显式选歌并跳转进度。

IndexedDB 当前有六张表：`lyric`、`trackDetail`、`playlistDetail`、
`trackSource`、`userPlaylists`、`miscCache`。
缓存使用 SWR：未过期直接返回；过期先返回旧值并后台刷新；未命中等待网络。
各表用 TTL 判断过期、LRU 控制条数，具体值见 [constants.js](../src/constants.js)。
歌曲详情、音频 URL、歌词、歌单和部分低频接口复用现有缓存层。

- `getPlaylistDetail(id, true)` 跳过缓存，用于需要立即刷新的操作。
- 评论各页直接走网络，不进入持久缓存；试听 URL 不进入持久缓存。
- `trackSource` 只存 URL，不保存音频文件，也不提供离线播放。
- `getMP3(id, br, { forceRefresh: true })` 绕过音源缓存并携带新时间戳；普通命中需匹配音质。
- 歌曲详情与音源缓存键统一为数值 ID；缓存读写异常不阻止网络播放，不修改数据库结构。
- 歌单首批 `tracks` 可能不完整，使用 `trackIds` 继续补齐歌曲详情。
- 退出/切账号作废播放任务及账号请求，清理音源URL缓存；迟到的旧音源不能重新写回。保留暂停队列、本机历史与偏好。
- 云写入统一检查端点业务响应；`playlist/tracks`可能返回嵌套`body`。写入后失效相关列表/详情缓存，旧请求不得回写覆盖新缓存；共享状态通知已打开详情刷新。
- 歌单名称和简介使用各自端点，不用批量更新覆盖无关标签；创建简介失败保留新ID，重试编辑已有歌单。
- `/local-playlist/:id`复用歌单详情，只读本机旧记录，不调用云歌单详情或自动上传。
- 搜索每类保留独立offset、loading、error、hasMore；失败不推进offset，新搜索或正常关闭作废旧页请求。
- 从搜索进入专辑时仅暂隐搜索层，保留原数据、分页及在途请求；后退至来源历史项恢复关键词、专辑标签、列表、滚动与焦点，前进再次隐藏。新搜索、清空或账号变化清理恢复元数据；数据不复制，仅内存保留，不新增 IndexedDB 缓存。
- `/album/:id` 复用登录守卫、共享播放器和 `TrackList`；浏览不自动播放。“播放全部”保留完整曲目队列，从首个 `playable !== false` 项开始；空专辑禁用按钮，全受限时提示并保留旧队列。搜索和歌手页提供专辑链接，播放器专辑文本仍无跳转入口。

## 维护约束

- 导入别名 `@` 指向 `src/`；存储键和默认值统一放入 `constants.js`。
- 路由视图必须保持单根节点，否则 `App.vue` 的过渡可能导致返回时白屏。
- 新增取歌接口接入可播放状态映射；修改播放逻辑保留 URL 失效重试。
- 复用现有 Store、缓存与 composables，避免另建播放器或缓存副本。
- 样式使用 [variables.scss](../src/assets/styles/variables.scss) 的主题变量。
- 弹窗通过 `useEscClose` 关闭栈顶；快捷键应避开输入框和按钮的默认操作。
- 格式以 [.prettierrc.json](../.prettierrc.json) 为准：无分号、单引号、行宽 80。
- 功能变化同步更新状态文档；源码入口表示已接入，不能替代真人验收。

## Vercel 部署

仓库支持前后端同站部署，无需另行部署 API 服务。

1. 导入本仓库，Root Directory 使用仓库根目录，Framework Preset 使用 Vite。
2. 平台 Node.js 选择 `24.x`；本地仍需满足根目录 `engines` 的小版本要求。
3. 保留 [vercel.json](../vercel.json) 的安装、构建和输出配置。
4. `VITE_NETEASE_API_URL` 使用 `/api`；已有平台同名变量也需保持一致。
5. 部署后检查公开 API、页面子路径刷新，再验证真实账号登录和播放。

`dist/` 提供静态页面；`api/index.js` 去掉 `/api` 前缀，复用初始化的后端。
函数打包包含后端 `module`、`util`、`plugins` 和 `data`，页面路径回退到 `index.html`。
因此仓库内后端和两端依赖锁文件都是运行资料，不能随意删除。

也可在根目录使用 CLI：

```sh
npx vercel
# 预览检查通过后发布
npx vercel --prod
```

`npm run build` 只生成前端；`npm run preview` 不会运行 Vercel API 函数。
预览时仍需可访问的 API，不能把静态页面打开当作前后端验证通过。

## 本地排障

先分别检查后端和开发代理，端口以启动日志为准：

```powershell
Invoke-RestMethod 'http://localhost:3000/song/detail?ids=347230'
Invoke-RestMethod 'http://localhost:5173/api/song/detail?ids=347230'
```

正常歌曲详情响应包含 `code: 200` 和非空 `songs` 数组。
公开接口成功不代表登录、歌单写入和实际音频播放成功。

| 现象 | 检查顺序 |
| --- | --- |
| 缺少模块或后端退出 | 检查后端依赖是否安装，再查看后端日志 |
| 端口占用 | 避免重复启动；改后端端口时同步修改 Vite 代理 |
| 请求超时 | 先直连后端，再检查 `/api`；区分上游和代理故障 |
| 登录失败或二维码过期 | 刷新二维码，核对手机授权、Cookie 和接口响应 |
| 返回 301 / 405 | 记录接口、参数和账号状态，不根据错误码断言唯一原因 |
| 只能试听或没有音频 URL | 检查账号权限与 `freeTrialInfo`，音质设置不能提升权限 |
| 跨域或 Cookie 异常 | 优先使用默认同域 `/api`，外置后端需另查凭证配置 |

如需改后端端口，在启动终端设置 `$env:PORT = '4000'`，
并把 Vite 代理目标改为 `http://localhost:4000`，再重启两端。
Windows 的 [start.bat](../start.bat) 会安装依赖并启动两端，打开固定的 5173 地址；
启动前会检查 Node 版本，不满足根目录 `engines` 时停止，不会自动修改系统安装。
排查启动问题时建议使用两个终端手动运行，便于查看日志。

## 验证与资料来源

`npm test` 单次执行 Vitest；`npm run test:watch` 监听测试。
测试位于 `tests/`，覆盖异步切歌、队列、失败策略、持久化、缓存、歌词及播放页。
Howler 与网络请求使用模拟，IndexedDB 使用内存实现；不登录或操作真实账号。
`npm run check` 依次执行 `check:lint`、测试和构建；只读检查包含 `src/`、`api/`、测试和配置。
第三方后端不纳入这个前端验收门槛；仍须按[验收清单](./功能状态与验收.md#手工验收)完成真人检查。
`npm run lint` 带自动修复；只检查时用 Oxlint、ESLint 的无修复模式。
全仓库检查包含第三方后端的存量问题，需区分已有报错和新增问题。
架构与交互参考 [YesPlayMusic](https://github.com/qier222/YesPlayMusic)，
后端来源和许可证见 [README](../README.md#致谢)。
