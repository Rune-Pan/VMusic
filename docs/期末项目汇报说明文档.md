### 1.2 项目背景

听潮从课程音乐网站需求出发，将登录、推荐、播放和个人中心组织成 Vue 3 单页应用。
项目参考 YesPlayMusic 的播放器与组件化思路，采用 Vue Router、Pinia、Howler 和
IndexedDB，并通过仓库内的 `@neteasecloudmusicapienhanced/api` 访问真实数据。

项目以桌面网页为目标，使用 Vite 构建与 Vercel 前后端同站部署，
不包含 Electron 的窗口、托盘和主进程运行链路。

### 1.3 需求与范围

当前有登录、首页、播放、歌单、个人中心、每日推荐、排行榜、歌手八个页面。
功能覆盖音乐发现、多类型搜索、歌词、个人偏好、评论查看和部分歌单操作。

与课程初稿的差异需明确说明：

- 使用真实 API，没有 Mock 数据目录或切换开关。
- 只登录已有网易云账号，没有注册、邮箱登录或独立账号后台。
- 主要面向桌面浏览器，移动端适配已移除。
- 歌单删除与资料修改只保留底层函数，部分歌单操作只更新本地数据。
- 试听与音质受上游和账号权限限制，不能承诺任意曲目完整播放。

完整需求和验收条件见[需求规格说明书](./需求规格说明书.md)，
详细状态见[功能状态与待办](./VMusic待办事项清单.md)。

## 2 代码设计与技术实现

### 2.1 技术选型与结构

| 技术                     | 作用                               |
| ------------------------ | ---------------------------------- |
| Vue 3 + Composition API  | 页面与共享组件                     |
| Vue Router               | 懒加载、登录守卫、页面跳转与滚动   |
| Pinia                    | 用户、播放、内容、界面四个状态域   |
| Vite + Sass              | 构建与样式                         |
| Axios                    | API 地址、凭证、响应和超时处理     |
| Howler.js                | 音频实例、事件、实际时长和播放控制 |
| Dexie / IndexedDB        | 业务数据与临时音频 URL 缓存        |
| `@lucide/vue` / `qrcode` | 图标与前端二维码生成               |

版本以 [package.json](../package.json) 与锁文件为准。
源码分为 `views`、`components`、`stores`、`api`、`composables`、`utils`。
目录、分层图与生产请求链路见[架构总览](./架构总览.md)。

工程使用单引号、无分号、2 空格缩进；Prettier 当前行宽为 80。
各视图保持单根节点，配合 `App.vue` 的路由过渡。

### 2.2 登录页面

源码：[LoginView.vue](../src/views/LoginView.vue)、[user Store](../src/stores/user.js)。

扫码通过 key 和轮询状态完成，账号模式内部切换密码 / 验证码。
表单校验后请求接口，成功时返回用户此前访问的页面。关键片段：

```js
const success = await userStore.login({
  account: form.account,
  password: form.password
})
if (success) {
  uiStore.showToast('登录成功', 'success')
  const redirect = route.query.redirect || '/'
  router.push(redirect)
}
```

### 2.3 推荐首页

源码：[HomeView.vue](../src/views/HomeView.vue)、[music Store](../src/stores/music.js)。

首页先请求分类，有已加载的推荐数据时不重复请求；分类组件和卡片组件负责展示。
核心加载片段（省略注释）：

```js
onMounted(async () => {
  await musicStore.fetchCategoryList()
  if (musicStore.recommendList.length === 0) {
    musicStore.fetchRecommend()
  }
})
```

加载中、空内容和正常网格分别渲染。数据来自 API，不是只过滤静态数组。

### 2.4 播放详情页面

源码：[PlayerView.vue](../src/views/PlayerView.vue)、[player Store](../src/stores/player.js)。

播放状态集中在 Store，页面展示封面、歌词和进度。
歌词轮询将播放器毫秒进度转成秒，再计算当前高亮行：

```js
function setLyricsInterval() {
  clearLyricsInterval()
  lyricsInterval = setInterval(() => {
    const currentTime = playerStore.progress / 1000
    updateHighlight(currentTime)
  }, LYRIC_POLL_INTERVAL)
}
```

音频加载后以实际时长更新进度，试听片段不套用完整曲目的时长。
歌词解析支持原文和翻译；页面卸载清理计时器。

### 2.5 歌单详情页面

源码：[PlaylistView.vue](../src/views/PlaylistView.vue)。

歌单详情先展示返回的曲目，再从完整 `trackIds` 补充更多歌曲。
播放全部把当前已加载曲目交给共享播放器：

```js
function playAll() {
  if (tracks.value.length > 0) {
    playerStore.setPlaylist(tracks.value, 0)
  }
}
```

页面还提供评论和分享。自己的歌单可移除歌曲，但该操作目前只更新本地列表与缓存，
没有向网易云请求删除；报告不能写成完整的服务端歌单 CRUD。

### 2.6 个人中心页面

源码：[ProfileView.vue](../src/views/ProfileView.vue)。

侧栏连接喜欢、歌单、历史和设置。外观、播放、快捷键、预加载按组展示。
音质偏好持久化后清理旧音频 URL 缓存，下一次播放按新偏好请求：

```js
function changeMusicQuality(value) {
  musicQuality.value = value
  localStorage.setItem(STORAGE_KEYS.MUSIC_QUALITY, String(value))
  clearTrackSourceCache().catch(() => {})
  uiStore.showToast('音质已更新', 'success')
}
```

本地历史与服务端历史分开；清空只作用于本地历史。
当前没有修改昵称、头像或删除歌单的界面入口。

## 4 创新性和解决方案的独特性

### 4.1 缓存与播放失败恢复

IndexedDB 保存歌词、歌曲详情、歌单、音频 URL 等。
TTL 判断过期，SWR 先使用旧值并后台更新，LRU 控制记录数量。
音频不下载保存；URL 失效后清缓存并重取一次。
这一设计减少重复请求，同时保留对临时地址失效的处理。

【待补充】缓存读写、TTL / LRU、失败重试代码截图及实际验证记录。

### 4.2 主题与快捷键

CSS 变量连接三种主题模式与四种主题色。快捷键支持七个操作、录制、冲突检测和重置。
默认 Space 播放暂停，其余操作使用 Alt 组合键；具体值见 `SHORTCUT_ACTIONS`。
输入框等编辑状态会跳过播放快捷键，减少操作干扰。

【待补充】深浅主题、主题色和快捷键设置截图。

### 4.3 可配置预加载

预加载总开关默认关闭，开启后可分别加载每日推荐、榜单、喜欢和歌单。
各请求独立处理失败，复用现有 Store 和缓存，没有另建一份数据系统。
不将该优化写成已测量的固定加载速度提升。

【待补充】预加载设置与网络请求对比记录。

### 4.4 多登录方式与歌词同步

扫码、密码和验证码覆盖不同登录操作；二维码图片由前端生成。
歌词按时间标签解析和匹配翻译，播放器进度驱动高亮与滚动。
异步状态与计时器清理是实现重点，效果需在真实账号和音频下验证。

【待补充】登录、歌词和进度交互的演示材料。
