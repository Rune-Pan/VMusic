# 听潮 架构总览

> 本文梳理 听潮 的分层架构、启动与执行流程、数据处理过程与缓存机制，作为代码导航与维护参考。详细约定见 `CLAUDE.md`，需求与设计见 `docs/` 其他文档。

## 一、分层架构

```
┌─────────────────────────────────────────────────────┐
│  视图层 views/  +  组件层 components/                  │
│  (Vue 单文件组件，<script setup> Composition API)      │
└───────────────┬─────────────────────────────────────┘
                │ 读写
┌───────────────▼─────────────────────────────────────┐
│  状态层 stores/  (Pinia: user / player / music / ui)  │
└───────────────┬─────────────────────────────────────┘
                │ 调用
┌───────────────▼─────────────────────────────────────┐
│  API 层 api/  (Axios 封装)                            │
│   ↕ SWR 接入                                          │
│  缓存层 utils/db.js  (Dexie / IndexedDB)               │
└───────────────┬─────────────────────────────────────┘
                │ HTTP
┌───────────────▼─────────────────────────────────────┐
│  Vite devServer 代理 /api → localhost:3000             │
│  NeteaseCloudMusicApi (网易云第三方 API)               │
└─────────────────────────────────────────────────────┘
```

跨层横切：`router/`（路由 + 权限）、`utils/request.js`（Axios 实例）、`utils/common.js`（工具函数）、`constants.js`（常量）、`composables/`（主题 / 歌词滚动）、`assets/styles/`（全局样式）。

## 二、应用启动与执行流程

```
main.js
  ├─ createApp(App)
  ├─ app.use(pinia) / app.use(router)
  ├─ 引入全局 SCSS (variables/global/transitions)
  └─ app.mount('#app')

App.vue onMounted
  ├─ userStore.restore()        ← 从 localStorage 恢复登录态
  ├─ playerStore.restore()       ← 恢复音量/循环/随机/当前曲目/播放列表
  ├─ musicStore.restorePlaylists()      ← 恢复本地歌单
  ├─ musicStore.restoreCategoryState()  ← 恢复分类缓存
  └─ userStore.fetchLikedSongs()        ← 拉取喜欢的歌曲 ID

App.vue 模板
  ├─ <Navbar v-if="登录且非播放页" />
  ├─ <main> <router-view><transition fade out-in> </main>
  ├─ <PlayerBar v-if="登录且有曲目" />
  └─ <ConfirmDialog/> <Toast/> <SearchResultsOverlay/>
```

**路由守卫**（`router/index.js`）：首次进入 `userStore.restore()` → 之后每次导航检查 `meta.requiresAuth`：未登录跳 `/login` 并携带 `redirect`；已登录访问 `/login` 跳首页；`scrollBehavior` 恢复/重置滚动。

七条路由：`/login`、`/`（首页）、`/player/:id`、`/playlist/:id`、`/profile`、`/daily-recommend`、`/toplist`。

## 三、状态管理（Pinia 4 个 store）

| store | 职责 | 持久化 |
|-------|------|--------|
| `user` | 登录态、用户信息、喜欢的歌曲 ID 集合 | localStorage `vmusic-user` |
| `player` | 当前曲目、播放列表、播放/暂停、进度、音量、循环/随机、本地播放历史 | `vmusic-player`（debounce 300ms）+ `vmusic-play-history` |
| `music` | 推荐、分类、搜索、歌词、用户歌单、服务端播放历史、排行榜 | `vmusic-playlists` + `vmusic-category-state`；IDB 缓存歌词 |
| `ui` | 全局确认弹窗、Toast 通知 | 无（瞬时态）|

**player 是播放状态唯一数据源**，封装 Howler.js。

## 四、数据处理过程（以"点击歌曲播放"为例）

```
用户点击歌曲 (TrackList / MusicCard)
  │
  ▼
playerStore.play(track, list)
  ├─ 记录上一首听歌时长 _lastListenDuration = howler.seek()
  ├─ 上报上一首 scrobble (听歌打卡，含实际时长)
  ├─ setPlaylist(list, index)
  └─ _replaceCurrentTrack(id, autoplay=true)
        │
        ├─ getTrackDetail(id)        ← api/track.js
        │     └─ SWR: 查 IDB trackDetail 表
        │           命中未过期→返回旧值
        │           过期→返回旧值 + 后台刷新写 IDB
        │           未命中→请求 /song/detail → 写 IDB
        │     → mapTrackPlayableStatus 标记 playable
        │     → currentTrack = track
        │     → _recordHistory(track)  ← 写本地播放历史
        │
        ├─ _getAudioSource(track)
        │     └─ getMP3(id)            ← api/track.js
        │           └─ SWR: 查 IDB trackSource 表（url，TTL 30 分钟）
        │
        └─ _playAudioSource(url, track)
              └─ new Howl({src, html5:true, ...})
                    ├─ onload → play() + 启动进度定时器
                    ├─ onloaderror → url 失效：clearTrackSource + 重拉一次
                    └─ onend → _nextTrackCallback（自然结束切下一首 + 上报时长）
```

**进度 / 歌词更新**：`setInterval`（250ms）轮询 `howler.seek()` 更新 `progress`；PlayerView 用 100ms 轮询 `playerStore.progress` 计算歌词高亮行。

## 五、缓存机制（IndexedDB + SWR）

集中封装于 `src/utils/db.js`（Dexie，库名 `vmusic`）。

**6 张表**：

| 表 | 存什么 | TTL | 上限 | 接入点 |
|----|--------|-----|------|--------|
| `lyric` | 解析后歌词数组（含翻译） | 7 天 | 500 | `music.fetchLyrics` |
| `trackDetail` | 歌曲 + privileges | 1 天 | 500 | `api/track.getTrackDetail` |
| `playlistDetail` | 歌单 + tracks + 订阅态 | 1 小时 | 100 | `api/playlist.getPlaylistDetail` |
| `trackSource` | 音频 url（不存字节） | 30 分钟 | 200 | `api/track.getMP3` |
| `userPlaylists` | 用户歌单列表 | 10 分钟 | 5 | `api/user.userPlaylist` |
| `miscCache` | 杂项（toplists/categoryList/recommend/评论首页） | 按 key 映射（评论 1 小时） | 20 | `cacheMisc`/`getMiscFromCache` |

**SWR 三态**：命中未过期→直接返回；过期→返回旧值 + 后台静默刷新；未命中→等网络。

**LRU**：命中更新 `lastAccess`，写入超限时按 `lastAccess` 删最旧。

`noCache=true`（用户强刷）跳过缓存直连网络。`player.js` 的 Howl `onloaderror` 清 url 缓存重拉一次防卡死。TTL 与上限常量集中在 `src/constants.js`（`CACHE_TTL_*` / `CACHE_MAX_*`）。

**不做音频字节缓存**：参考上游 YesPlayMusic，其 `cacheTrackSource` 仅在 `process.env.IS_ELECTRON` 下把音频 ArrayBuffer 存 IndexedDB（默认 8GB 上限 + LRU），Web 构建第一行直接 `return` 不缓存。本项目是 Vite 网页应用（非 Electron），且音频字节落本地有容量配额限制（一首 320kbps 约 8-10MB）与版权风险，故只缓存临时 url，不缓存字节。当前缓存水平已对齐上游 Web 版。

## 六、关键约束

- **视图单根节点**：`<transition mode="out-in">` 要求各视图单根，多根会破坏过渡导致返回空白。
- **常量集中**：`src/constants.js` 统一 localStorage 键名、TTL、上限、轮询间隔等，避免硬编码。
- **参考实现优先**：改动前参考本地 `YesPlayMusic-master`（路径见 `CLAUDE.md`）。
